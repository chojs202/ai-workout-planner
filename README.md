# Fit Plan — AI Workout Planner & Tracker

AIによるトレーニングルーティンの提案から、運動記録と振り返りまでを管理するWebアプリです。

React・TypeScriptによるフロントエンドと、Express・MongoDBによるバックエンドを個人で開発しました。

- **アプリ:** https://fit-plan-s86c.onrender.com/
- **サービス紹介:** https://fit-plan-s86c.onrender.com/about
- **対応言語:** 日本語・韓国語・英語

## 開発の目的

トレーニングの計画と実際の記録をつなげ、継続的に振り返れるサービスを目指しました。

AIによるルーティン生成に加えて、ルーティンの編集、セットごとの実績入力、過去の記録修正、種目別の比較まで、一連の操作を実装しています。

## 主な機能

### アカウント管理

- メールアドレスとパスワードによる新規登録・ログイン
- HttpOnly Cookieを使用したJWT認証
- 名前・パスワードの変更
- メール認証コードによるパスワード再設定
- アカウント削除

### ルーティン管理

- ルーティンの作成・編集・削除
- 日別の種目、対象部位、休憩時間、セット内容の設定
- 日別ルーティンの折りたたみ表示
- 目標、経験、場所、使用器具などに基づくAIルーティン提案

### トレーニング記録

- ルーティンを選択してトレーニングを開始
- セットごとの回数・重量・完了状態の記録
- トレーニングメモの保存
- 完了後の記録修正と個別種目の編集
- カレンダーでの実施日確認

### 履歴・振り返り

- 履歴の検索・絞り込み・並べ替え
- 履歴一覧のページネーション
- 種目別の重量・回数などの比較
- トレーニング履歴に基づくAIフィードバック

### UI・操作性

- 日本語・韓国語・英語の切り替えと選択言語の保存
- モバイル画面を考慮したレイアウト
- 共通デザインの確認モーダル
- 未保存の変更がある場合の画面遷移確認
- 保存完了トースト
- ページ・言語に応じたブラウザータブタイトル
- 404ページ
- リンク共有用のOG画像

## データ構成

主に以下の3種類のデータを管理しています。

| データ  | 役割                                     |
| ------- | ---------------------------------------- |
| User    | アカウント情報と認証に使用する情報       |
| Routine | トレーニング計画と日別の種目・セット設定 |
| Workout | 実施したトレーニングと各セットの実績     |

Workoutには、実施時のルーティン名、種目名、目標値などを保持します。

ルーティンの設定と実施記録を分けることで、計画と実績を比較し、過去の記録を独立して管理できる構成にしています。

## 工夫した点

### 計画と実績を分けたデータ設計

目標の回数・重量と、実際に行った結果を分けて保存しています。

完了後の記録にも編集機能を用意し、入力ミスを後から訂正できるようにしました。

### 編集操作の一貫性

ルーティン編集と記録編集で、種目名・対象部位・休憩時間・セット内容を扱えるようにしています。

また、未保存の変更がある場合は共通モーダルで確認し、変更内容を失わないように操作を選択できる構成にしました。

### 多言語対応

翻訳データを日本語・韓国語・英語に分割し、共通の翻訳キーで参照しています。

フォームのエラーや操作結果、パスワード再設定メール、ブラウザータブのタイトルも多言語に対応しています。選択言語に合わせてHTMLのlang属性も更新します。

### ローディング表示の整理

認証確認、ページコードの読み込み、API取得によって複数のローディング表示が切り替わっていたため、App側の共通表示に集約しました。

データを取得するページから準備状態を通知し、内容が画面に反映されるまで表示を維持する構成にしています。

### 初期表示の改善

React.lazyとSuspenseでページ単位にコードを分割しています。

LighthouseでフォントCSSによる表示の遅延を確認し、選択言語に応じて必要なフォントCSSを読み込む方式に変更しました。

また、Webフォントの読み込み完了までローディング画面を維持していた処理を見直しました。

## ローカルでの実行

### 必要な環境

- Node.js 24.x
- npm
- MongoDBの接続先
- AI機能を利用する場合はOpenAI APIの利用設定
- メール機能を利用する場合はBrevoの利用設定

### 1. パッケージのインストール

リポジトリのルートで実行します。

```bash
npm install
```

### 2. 環境変数の設定

`client/.env`を作成します。

```dotenv
VITE_API_BASE_URL=http://localhost:5000
```

`server/.env`を作成します。

```dotenv
PORT=5000
CLIENT_URL=http://localhost:5173

MONGODB_URI=your_mongodb_connection_string
JWT_SECRET=your_random_secret

OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=your_available_model

BREVO_API_KEY=your_brevo_api_key
BREVO_SENDER_EMAIL=your_verified_sender_email
BREVO_SENDER_NAME=Fit Plan
```

各値は自分の環境に合わせて設定してください。

Brevoの送信元メールアドレスには、利用する送信元として確認済みのアドレスを指定してください。

秘密情報を含む`.env`はGitにコミットしないでください。

### 3. 開発サーバーの起動

ターミナルを2つ開き、それぞれリポジトリのルートで実行します。

フロントエンド:

```bash
npm run dev:client
```

バックエンド:

```bash
npm run dev:server
```

| 接続先         | URL                              |
| -------------- | -------------------------------- |
| フロントエンド | http://localhost:5173            |
| バックエンド   | http://localhost:5000            |
| ヘルスチェック | http://localhost:5000/api/health |

### 4. ビルド

リポジトリのルートで実行します。

```bash
npm run build
```

### 5. テスト

クライアントとサーバーのテストをそれぞれ実行します。

```bash
npm run test --workspace client
```

```bash
npm run test --workspace server
```

以下の処理に対するテストを配置しています。

- 運動記録からの集計・種目別進捗の計算
- Workoutの取得・更新・削除などで使用するユーザー条件
- Workoutルートの認証処理
- リクエスト回数制限

画面操作を含む一連のユーザーフロー全体を検証するE2Eテストは、今後の改善対象です。

## デプロイ構成

Render上でExpressサーバーを起動し、ビルドしたReactアプリも同じサービスから配信しています。

- MongoDB Atlasでデータを保存
- Brevo APIでパスワード再設定メールを送信
- UptimeRobotでヘルスチェックを監視
- 公開紹介ページ用のサイトマップを配置

ヘルスチェックの`/api/health`は、サーバーの応答を確認するエンドポイントです。データベースや外部APIの動作全体を検証するものではありません。

## 制限事項

- Renderの無料プランを利用しているため、初回アクセス時などに起動待ちが発生する場合があります。
- AI機能は外部APIの利用状況や制限により、応答時間や利用可否が変わります。
- AIの提案は参考情報です。体調や経験に合わせて調整してください。
- Lighthouseのスコアは、通信状態や端末などの測定環境によって変動します。
